## Why this matters

Verified at f53bf0e: there is **no ESLint config anywhere** (`ls .eslintrc* eslint.config.*` → none), so `bun run lint` drops `next lint` into an interactive config prompt and **exits 1** — lint has effectively never run on this codebase. `next lint` is also deprecated and removed in Next 16, so this migration is forced regardless. Separately, there is no `.github/` directory at all: nothing enforces `type-check`, lint, or tests on push, and Vercel deploys `main` directly. For a repo where ~190 tasks were executed by coding agents, an enforced one-command verification gate is the highest-leverage guardrail available.

The exact failure, captured at f53bf0e:

```
$ CI=1 bun run lint

npx @next/codemod@canary next-lint-to-eslint-cli .
? How would you like to configure ESLint? ...
error: script "lint" exited with code 1
```

## Scope

**In scope**:
- `eslint.config.mjs` (or the file the codemod produces)

- `.github/workflows/ci.yml` (create)
- Mechanical lint fixes in `src/**` and `e2e/**` **only** where `eslint --fix` resolves them automatically; manual edits only for trivial cases (unused imports, `prefer-const`).

- `next.config.js`, `vercel.json`, `tsconfig.json`.
- Any behavioral code change to satisfy a lint rule — disable the rule with a line comment and a one-word reason instead, and list every such disable in your report.
- Upgrading Next.js itself (separate decision; see the findings table).
- Prettier/formatter setup.

## Steps

### Step 1: Run the official codemod

```
bunx @next/codemod@canary next-lint-to-eslint-cli .
```

Accept the non-interactive defaults if prompted (choose the **strict** / core-web-vitals preset if asked). Expected effects: an `eslint.config.mjs` appears extending Next's flat config, the `lint` script changes to invoke `eslint` directly, and eslint moves to ^9 in devDependencies. Run `bun install` afterward so `bun.lock` matches.

**Verify**: `ls eslint.config.*` → exactly one file; `grep -n '"lint"' package.json` → no `next lint`.

### Step 2: Get to a clean lint

Run `bun run lint`. If it reports problems: first `bun run lint -- --fix` (or `bunx eslint . --fix` matching the new script), then handle the remainder per the scope rules (trivial manual fixes allowed; rule-disables with reasons otherwise). If there are more than ~50 errors after `--fix`, STOP and report the count and top rule offenders instead of bulk-editing.

**Verify**: `bun run lint` → exit 0. `bun run type-check` → exit 0. `bun run build` → exit 0.

### Step 3: Add the CI workflow

Create `.github/workflows/ci.yml`:

```yaml
name: CI
on:
  push:
    branches: [main]
  pull_request:

jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: oven-sh/setup-bun@v2
        with:
          bun-version: latest
      - run: bun install --frozen-lockfile
      - run: bun run type-check
      - run: bun run lint
      - run: bun run test   # remove this line if plans/003 has not landed, and say so in your report
```

Deliberately excluded from CI: the Playwright e2e suites (need a dev server + browser download; they stay a local/pre-release step) and `bun run build` (Vercel already builds every push; duplicating it doubles CI time for little signal — note this reasoning as a comment in the YAML).

**Verify**: `bunx yaml-lint .github/workflows/ci.yml 2>/dev/null || bun -e "const fs=require('fs');const y=fs.readFileSync('.github/workflows/ci.yml','utf8');console.log(y.includes('setup-bun')?'ok':'missing')"` → `ok` (sanity only); every command in the workflow (`bun install --frozen-lockfile`, `bun run type-check`, `bun run lint`, `bun run test`) passes locally.

### Step 4: Honest local dry-run

Run the exact CI sequence locally from a clean state: `bun install --frozen-lockfile && bun run type-check && bun run lint && bun run test`.

**Verify**: exit 0 end-to-end.
